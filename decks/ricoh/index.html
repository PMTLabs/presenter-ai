05 · CURRENT DELIVERY MODEL

Current Hybrid Working Model

Current Operating Flow

CPE/DCD Backlog Item or Ad-Hoc Request (in Azure DevOps)
Ad-hoc requests arrive via end-user or dealer email
↓
Clarification, Estimation & Assignment
↓
Development / Fix & FPT Testing
↓
Release & Closure

How the Current Model Behaves

  • CPE and DCD already run against a defined roadmap and backlog.
  • Ad-hoc requests layer on top, with volume that varies week to week.
  • Planned backlog and ad-hoc request volume compete for the same capacity.
  • No consistent Story Point or velocity baseline has been established.

Why Change Is Proposed

  • Formalize planning predictability for CPE/DCD.
  • Make ad-hoc request/support consumption visible.
  • Protect planned backlog from unpredictable ad-hoc request volume.
Current strength: high responsiveness. Current limitation: unpredictable ad-hoc request volume can crowd out planned backlog work.
