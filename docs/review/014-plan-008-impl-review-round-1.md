## Findings

1. **D · blocker — a confirmed side effect can be replayed by the HTTP auth handler.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpConnector.cs:278-311`. `IsToolCall` scans raw bytes for the exact text `"tools/call"`, rather than parsing JSON-RPC's `method`. A semantically identical valid JSON request containing `"method":"tools\/call"` (or one with escaped characters) is misclassified as a non-call; if that server performs the action then returns 401, the handler refreshes and sends the same POST again without a second spoken yes. Conversely an initialize/list request with that exact quoted string in another field is misclassified as a call and never refreshed. This is a security-sensitive protocol distinction, not a harmless optimization. **Fix:** identify the actual JSON-RPC method structurally, or explicitly mark the request as call/non-call in the transport; default ambiguous/batched bodies to *never retry*. Add a handler test with escaped method and side-effect counter.

2. **D · should-fix — byte-budget omission leaves tools undiscoverable.** `src/PresenterAi.Application/Tools/ToolSessionCatalogue.cs:45-72,151-162`. With ≤16 total tools, a few valid 4 KiB schemas and long descriptions can exceed 32 KiB; `TryAddSessionInline` skips later definitions and claims they "remain searchable", but `find_tools`/`call_tool` are only installed on **count** overflow. Those tools cannot be offered or discovered in that talk. **Fix:** switch to discovery mode when the prospective inline payload exceeds the budget, retaining omitted session tools in the search snapshot; exercise ≤16 tools whose combined definitions exceed 32 KiB.

3. **D · should-fix — pre-registered OAuth reconnect does not reuse stored registration.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpOAuthService.cs:67-78,99-139`; `web/app/src/routes/Tools.tsx:76-103`. `StartAsync` never reads/decrypts existing OAuth credentials to retrieve `ClientId`/`ClientSecret`, while the page clears the fields after initial connect. On expiry/invalid grant, clicking Reconnect with no input selects metadata registration or dynamic registration, or returns `tools_oauth_client_required` even though the encrypted pre-registration is already stored. **Fix:** when reconnecting, reuse the owner's saved registration from the protected credential unless the caller explicitly supplies a replacement; retain the owner/status checks and test reconnect with no fields.

4. **D · should-fix — OAuth completion claims connected before validating the MCP connection.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpOAuthService.cs:170-192`; `src/PresenterAi.Api/Endpoints/ToolEndpoints.cs:346-366`. Given a valid token response but a server whose `initialize`/`tools/list` rejects that token, `/oauth/complete` returns a `connected` server without listing any tools; the first talk skips it. The plan explicitly requires completion to list tools and acceptance criterion 1 requires the user to see them. **Fix:** test guarded MCP connect/list on completion, update status/error appropriately, and show reconnect on auth failure without echoing remote errors.

5. **A · should-fix — auth/credential failures are marked `needs_reconnect` during talk load but overwritten as `error` on REST test.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpSessionToolSource.cs:148-164` versus `src/PresenterAi.Api/Endpoints/ToolEndpoints.cs:404-418,460-474`; similarly `ToolEndpoints.cs:268-278`. When the encrypted key changes or the token refresh fails, connector marks `needs_reconnect`, but `/test` catches `McpConnectorException` and overwrites it with `error`, so the UI hides the Reconnect action (`Tools.tsx:247-261`). The list route collapses those codes to unreachable. **Fix:** centralize stable-code → status/problem mapping and apply it on start, credential, test and list paths; test the same key-change/refresh failure across all three routes.

6. **D · should-fix — a failed refresh may overwrite a concurrent winner's connected status.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpOAuthService.cs:229-258`; `src/PresenterAi.Infrastructure/Tools/Mcp/McpConnector.cs:153-166`. A lease holder observes unchanged credential and fails refresh; another request saves a new token just after `FreshAsync` but before `SetStatusAsync(needs_reconnect)`. The status update has no version condition and marks the newly refreshed credential disconnected. Connector's unconditional status update after an exception similarly ignores the winner. **Fix:** make failure's status change conditional on the same `xmin` version (and avoid unconditional connector status writes); re-read and use the winner on CAS failure. Add an interleaving test at the last read/status write, not only overlapping token exchanges.

7. **D · should-fix — untrusted metadata is included in server/page log lines.** `src/PresenterAi.Infrastructure/Tools/Mcp/McpTool.cs:180-185`, `McpSessionToolSource.cs:90-93,143-166`; `src/PresenterAi.Application/Presenting/Presenter.cs:1262,1289,1406-1408,1466-1470`. A remote server can set its tool name/title (or the owner can set the server name) to newline, control characters or a secret-shaped string; those fields become structured server-log fields and interpolated page-log strings. `ResourceLinkBlock` names/URI are also included in results (`McpTool.cs:212-231`), although results are intentionally untrusted model data. The plan's "arguments and results never logged" is substantially implemented, but the log's untrusted **tool label** has no length/control-character restriction beyond generated tool-name length. **Fix:** normalize/control-escape labels and notes before logging, use stable IDs for log correlation, and add a hostile metadata/log sink test; keep result contents out of log templates.

8. **D · should-fix — `alwaysAsk:false` override masks the server-level permission in the tools API/UI.** `src/PresenterAi.Api/Endpoints/ToolEndpoints.cs:450-458`; `src/PresenterAi.Infrastructure/Tools/Mcp/McpSessionToolSource.cs:95-103`. For a read-only tool with persisted override false, then server `alwaysAsk=true`, runtime correctly requires a yes (OR), but `/tools` responds `alwaysAsk:false`; the page renders its switch off (`Tools.tsx:431-438`). **Fix:** return effective `alwaysAsk = !isReadOnly || server.AlwaysAsk || overrideTrue` (or expose server/override separately and compute effective status); test turning on server override *after* saving a false tool override.

9. **C · should-fix — no-key behavior in the guide/plan is unsupported on the OAuth no-auth route.** `docs/guides/003-external-tools.md:63` says "unauthenticated servers still work"; `src/PresenterAi.Api/Endpoints/ToolEndpoints.cs:309-310` returns 503 before probing a server that could be credential-free. Users without `Tools:CredentialKey` cannot use **Connect** to mark a public no-auth server connected despite the documented path. **Fix:** probe first, return the no-auth connected result without a key; check for the key only before creating OAuth state or storing credentials.

10. **B · should-fix — outbound named-client test identifies configuration by too few fields.** `tests/PresenterAi.Infrastructure.Tests/Tools/OutboundGuardTests.cs:137-153`. A wrong DI implementation that still registers a guarded singleton `SocketsHttpHandler` but configures the `mcp` and `mcp-oauth` named clients with a fresh, unguarded auto-redirecting handler passes: the test checks the singleton properties and only that `CreateClient` succeeds, not either client's actual transport. **Fix:** send requests through each named client using a fake DNS/socket seam; assert blocked IPs are never connected, redirects are refused, caps apply, and no proxy is used.

11. **B · should-fix — MCP 404 read-only retry test does not identify the number of effects/requests.** `tests/PresenterAi.Infrastructure.Tests/Tools/McpToolSourceTests.cs:347-374`. A wrong implementation that reconnects and sends `get_price` twice after a 404 still returns `ok` with message `123.45`, satisfying the assertions; it violates "reconnect once and retry" and can waste rate limits. **Fix:** assert the test server's exact request counts and that a second 404/401 is not replayed. (The confirmed-action 401/404 tests at `:271-345` *do* assert their side-effect counter.)

12. **B · should-fix — OAuth integration does not identify tool-list completion.** `tests/PresenterAi.Integration.Tests/Tools/ToolEndpointIntegrationTests.cs:59-116`; `tests/PresenterAi.Integration.Tests/Tools/McpOAuthTests.cs:112-136`. A wrong `/oauth/complete` implementation that saves a token and reports connected without ever calling `tools/list` passes these paths, although §3.6 step 3 calls for listing. **Fix:** assert observable tools-list calls and response/status on a server rejecting an exchanged token.

13. **B · nit — web UI badges oracle only tests the default override combination.** `web/app/src/routes/Tools.spec.tsx:17-26,128-151`. A UI/API that shows `Always ask` unchecked when a persisted false tool override conflicts with server `alwaysAsk:true` passes because all fixtures have server `alwaysAsk:false`. **Fix:** add a server-true/override-false effective-badge case. The OAuth callback test (`ToolsOAuthCallback.spec.tsx:1-54`) covers basic completion/navigation, but not loss of access token on redirect (the shared client refresh-once contract); exercise callback using a real client refresh mock.

14. **C · nit — guide overstates the talk-start time bound.** `docs/guides/003-external-tools.md:48` says "Tools are loaded at talk start in parallel within a 3-second budget"; `Presenter.cs:505-533` uses `StartBudgetMs + 1000 ms` as a hard cap while `McpSessionToolSource.cs:46-55` starts its 3-second server timer only after repository reads and overrides. **Fix:** distinguish the per-server 3-second budget from the presenter-wide 4-second cap in docs.
