**Date:** 2026-09-23. **Repository part:** `pi` `openai-codex/gpt-5.6-luna:high`, read-only, request `p008-scout-01`,
against `develop` @ `0a30aa3`. Key claims were spot-checked by the orchestrator (bridge `start` frame and event

## Summary

- The talk owner's id reaches `Presenter.StartAsyncCore` (from `ClientConnection.UserId`) but not `SessionRequest` or
  `LiveSession`; plan 008 loads the owner's tools on the Start path, next to the presentation load.
- No Data Protection, no credential column, no outbound HTTP guard, and no MCP package exist today. The only
  encryption is AES-GCM for transient SSO state with a config key (`OAuth:StateEncryptionKey`).
- The existing SSO flow (API callback → browser redirect to the app → the app posts a one-time code) is the pattern
  for binding an OAuth completion to the signed-in user.
- Tests: `FakeLiveServer` (loopback Kestrel) and `IntegrationApiFactory` (Testcontainers Postgres/Redis) are the hosts
  to reuse; the web client is generated from the checked-in `web/shared/openapi/v1.json`, which `OpenApiTests`
  compares with the live document.

## Official C# MCP SDK (Context7, NuGet, 2026-09-23)

- **Packages:** `ModelContextProtocol.Core` (client and transports), `ModelContextProtocol` (hosting/DI extras),
  `ModelContextProtocol.AspNetCore` (server hosting; used here for the in-process test server). Latest stable on
  nuget.org: **2.2.0** for all three. The local NuGet cache holds only 1.3.0.
- **Client:** `new HttpClientTransport(new HttpClientTransportOptions { Endpoint, TransportMode =
  HttpTransportMode.StreamableHttp, ConnectionTimeout, AdditionalHeaders }, httpClient, loggerFactory,
  ownsHttpClient: false)` then `await McpClient.CreateAsync(transport)`. The overload that takes an `HttpClient` lets
  the caller supply its own handler chain (the SSRF guard and the auth handler).
- **Tools:** `client.ListToolsAsync()` → `IList<McpClientTool>`; `tool.CallAsync(Dictionary<string, object?>)` →
  `CallToolResult` with `Content` blocks (`TextContentBlock`, `ImageContentBlock`, `AudioContentBlock`,
  `EmbeddedResourceBlock`), `StructuredContent` and `IsError`. Annotations are on the protocol `Tool`
  (`Annotations.ReadOnlyHint`); per the MCP spec an absent hint means "not read-only".
- **OAuth in the SDK:** `HttpClientTransportOptions.OAuth` (`ClientOAuthOptions`) with an
  `AuthorizationCallbackHandler` (the older `AuthorizationRedirectDelegate` is obsolete: no state or RFC 9207 issuer
  validation). It is built for an interactive client that opens a browser and listens for the redirect itself (the
  `ProtectedMcpClient` sample runs a local listener). A web API whose redirect lands in a different HTTP request needs
  its own authorization-code flow; the SDK is then used for transport only, with the bearer token added by a handler.

## Repository scout (p008-scout-01)


### 1. Identity

- Access tokens are JWTs. `TokenService.GetUserAsync` reads `sub` first (`JwtRegisteredClaimNames.Sub`), then `NameIdentifier`; token issuance writes `sub`, email, role, `jti`, and optional `display_name`. There is no `ICurrentUser`-style abstraction; REST handlers receive `ClaimsPrincipal` directly. (`src/PresenterAi.Api/Auth/TokenService.cs:136-150`, `src/PresenterAi.Api/Auth/TokenService.cs:160-181`)
- SSO is an OAuth authorization-code + PKCE flow. The SSO endpoints are under `/v1/auth/sso`; callback identity resolution creates/links `User` and stores the one-time code in the SSO code store. Development sign-in is conditionally mapped only when `Auth:Dev:Enabled` and the host is Development; it upserts the configured development user and issues the same JWT/refresh-token response. (`src/PresenterAi.Api/Endpoints/AuthEndpoints.cs:24-116`, `src/PresenterAi.Api/Endpoints/AuthEndpoints.cs:189-216`, `src/PresenterAi.Infrastructure/Identity/SsoService.cs:92-189`)
- REST presentation handlers repeat the claim extraction locally in `OwnerId`; `/v1/auth/me` instead calls `TokenService.GetUserAsync`. (`src/PresenterAi.Api/Endpoints/PresentationEndpoints.cs:31-71`, `src/PresenterAi.Api/Endpoints/PresentationEndpoints.cs:103-107`, `src/PresenterAi.Api/Endpoints/AuthEndpoints.cs:169-184`)
- The browser first calls authenticated `POST /v1/sessions/ticket`. The endpoint reloads the user and puts `user.Id` in Redis under a short-lived opaque ticket. The bridge consumes the first WebSocket `auth` frame, claims the ticket, and returns `(UserId, TakeOver)`. (`src/PresenterAi.Api/Endpoints/SessionEndpoints.cs:16-43`, `src/PresenterAi.Infrastructure/Redis/TicketStore.cs:23-43`, `src/PresenterAi.Api/Realtime/PresenterBridge.cs:177-247`)
- `ClientConnection.UserId` is set directly by `new ClientConnection(socket, authentication.Value.UserId, ...)`; the `ClientConnection` constructor assigns it. The `start` frame passes that value to `IPresenter.StartAsync(..., connection.UserId, ...)`. (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:80-85`, `src/PresenterAi.Api/Realtime/PresenterBridge.cs:360-367`, `src/PresenterAi.Api/Realtime/PresenterBridge.cs:514-536`)

### 3. Secrets at rest

- No ASP.NET Core Data Protection registration or persisted key ring was found in the opened API/Infrastructure wiring; `AddDataProtection` and key-ring persistence are not used. (`src/PresenterAi.Api/Program.cs:24-57`, `src/PresenterAi.Infrastructure/DependencyInjection.cs:17-73`)

### 4. REST conventions

- The API uses ASP.NET Core minimal APIs. `Program` maps endpoint groups for health, presentations, config, auth, sessions, the WebSocket bridge, and OpenAPI; the REST resource prefix is `/v1`. (`src/PresenterAi.Api/Program.cs:166-181`, `src/PresenterAi.Api/Endpoints/PresentationEndpoints.cs:12-27`)
- Presentation routes are declared in `PresentationEndpoints`: `GET /v1/presentations` and `GET /v1/presentations/{id}`. The group requires authorization and the default CORS policy. (`src/PresenterAi.Api/Endpoints/PresentationEndpoints.cs:14-39`, `src/PresenterAi.Api/Program.cs:91-92`)

(`src/PresenterAi.Api/Errors/Problems.cs:5-25`, `src/PresenterAi.Api/Errors/DomainExceptionHandler.cs:8-58`)

### 6. Start path

### Surprises and risks

- **Owner identity is lost at the live boundary.** It is present in the WebSocket connection and presenter start/load path, but current `SessionRequest` and `LiveSessionConfig` do not carry it. (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:360-367`, `src/PresenterAi.Application/Presenting/Presenter.cs:7-7`, `src/PresenterAi.Infrastructure/DependencyInjection.cs:145-148`)
- **Presenter lifetime/DI mismatch matters.** The presenter is singleton while repositories/DbContexts are scoped; current code deliberately creates a scope per load. MCP credential and connection code must not capture a scoped context in the singleton or hold a database context across a live session. (`src/PresenterAi.Infrastructure/DependencyInjection.cs:127-151`)
- **No production auto-migration path was found.** Deployment must apply migrations separately; adding an encrypted credential schema requires an explicit migration/application step. (`src/PresenterAi.Infrastructure/Persistence/PresenterAiDbContextFactory.cs:6-18`, `tests/PresenterAi.Integration.Tests/MigrationsApplyToPostgresTests.cs:11-22`)
- **The outbound surface has no SSRF guard today.** The only generic HTTP client is SSO and the live connection is a raw WebSocket; Plan 008's guard must cover URL validation, DNS/IP checks and redirects for every MCP/OAuth request rather than relying on existing options validation. (`src/PresenterAi.Api/Program.cs:36-40`, `src/PresenterAi.Infrastructure/Identity/SsoService.cs:194-224`, `src/PresenterAi.Infrastructure/Live/LiveSession.cs:126-143`, `docs/progress/018-handoff-plans-007-008.md:48-60`)
- **There is no application encryption-at-rest abstraction.** Custom AES-GCM protects transient OAuth state, while database refresh tokens are hashes; MCP credentials need a new key-management decision without introducing plaintext logging/serialization. (`src/PresenterAi.Infrastructure/Identity/SsoService.cs:255-279`, `src/PresenterAi.Api/Auth/TokenService.cs:38-49`)
- **Plan 007 is a hard dependency and not implemented in this branch.** Its registry/catalogue, confirmation phases, live tool events, and immutable snapshot are plan text only; Plan 008 must not target nonexistent types without first landing 007. (`docs/plan/007-voice-control-and-tool-protocol.md:92-139`, `docs/research/006-voice-control-and-tools-scout.md:9-13`)
- **Hosted tools are currently unreachable.** The research describes the GPT-Live Responses tool cycle, but the current payload has no tools and `LiveSession` only forwards terminal response events. (`docs/research/005-gpt-live-delegation-audience-questions.md:181-221`, `src/PresenterAi.Infrastructure/Live/LiveSession.cs:550-566`)
- **Tests provide useful hosts but no MCP protocol fixture.** `FakeLiveServer` is a WebSocket fake and `IntegrationApiFactory` is the real API host; Plan 008 needs a separate Streamable HTTP MCP test server and SSRF/redirect/DNS tests. (`tests/PresenterAi.Infrastructure.Tests/Live/FakeLiveServer.cs:40-91`, `tests/PresenterAi.Integration.Tests/Support/IntegrationApiFactory.cs:8-72`, `docs/progress/018-handoff-plans-007-008.md:121-129`)
- **Page logging is a constrained channel.** The bridge forwards structured log strings and the page retains only bounded in-memory arrays; external tool calls must avoid arguments/results and fit current `log` frames or add a documented protocol event. (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:57-67`, `web/app/src/store/presenterStore.ts:36-78`, `docs/progress/018-handoff-plans-007-008.md:108-112`)
