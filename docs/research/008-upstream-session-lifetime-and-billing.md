# 008 — Upstream session lifetime and billing exposure

**Date:** 2026-09-23. **Scout:** `pi` `openai-codex/gpt-6-sol:medium`, read-only, request `s-idle`, on `feature/008-mcp-external-tools`. **Question (user):** how do we make sure an idle or stopped call disconnects the upstream completely, so there is no unexpected charging? The orchestrator checked the two high-risk claims against the code: `PauseCore` (`Presenter.cs:1686-1701`) leaves the upstream open, and no server-side idle or maximum-duration cap exists (only the CLI `--max-seconds`, default 300 s).

---

# s-idle — upstream lifetime and billing exposure

Executive summary (five lines):
- A healthy End requests `session.close`, waits up to 5 s, then aborts and ultimately disposes the upstream socket (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:246-299`; `src/PresenterAi.Application/Presenting/Presenter.cs:1772-1827`).
- An authenticated browser can stay connected and silent indefinitely; pause and stalled narration leave the upstream open, with a 20 ms silence pump (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:289-324`; `src/PresenterAi.Application/Presenting/Presenter.cs:1556-1586,1686-1701`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:399-445`).
- Browser disconnect normally ends the talk, but start/close observation bounds can release ownership before a stuck presenter loop becomes idle (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:20-29,140-164,441-469`).
- Live-session retries dispose failed candidates before fallback; active tools and delegated web search lack an end-linked cancellation guarantee (`src/PresenterAi.Application/Presenting/Presenter.cs:543-593,1356-1376,1772-1791`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:630-665`).
- Usage and close reason are logged/recorded, but a missing final upstream usage is unconfirmed and the persisted fallback is merely last usage or zero (`src/PresenterAi.Application/Presenting/Presenter.cs:1849-1863`; `src/PresenterAi.Infrastructure/Sessions/SessionRecorder.cs:333-380`).

## Closure paths and latency

- Normal slide progression: output triggers slide silence/part timers; last slide invokes wrap-up; after voiced wrap-up + silence it queues End, or after 15 s without wrap-up audio the fallback queues End (`src/PresenterAi.Application/Presenting/Presenter.cs:1526-1554,1590-1622`). A slide with *no* output nudges at 15 s and 30 s, then pauses at ~45 s rather than closing (`src/PresenterAi.Application/Presenting/Presenter.cs:32-34,1556-1587`). On End, `CloseAsync` sends `session.close`, waits 5 s for `session.closed`, aborts on timeout; `SessionClosed` is processed later by the presenter loop and `DisposeAsync` aborts/joins loops/disposes socket (`src/PresenterAi.Application/Presenting/Presenter.cs:1772-1827`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:246-299,738-760`). Thus normal cooperative closure can finish sooner; timeout is ~5 s after End reaches the event loop, plus queue delay.
- Browser End uses `EndAsync` from the receive loop (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:386-393`). Browser close/tab teardown/network drop **when detected by ReceiveAsync or RequestAborted** enters `finally`, waits for start observation up to 90 s, requests End if non-idle, waits up to 5 s for idle, and attempts recorder flush before freeing the slot (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:128-173,289-311,441-469`). A blackholed TCP/browser that never yields a receive error/close is not detected by an application heartbeat here (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:289-324,392-393`). A background tab stays billed if still connected and presenting/paused; frontend disconnects on component cleanup, but this is not a server guarantee (`web/app/src/routes/Present.tsx:101-107,150-156`).
- Takeover: old holder is sent `taken_over` + 4409; socket aborted after 1 s if necessary; new connection waits for old holder's `Released` (up to 15 s), so normal takeover waits for old End/recorder cleanup rather than starting a concurrent presentation (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:85-120,140-173,574-610`). If holder does not release in 15 s, newcomer receives busy; not a forced upstream termination (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:20-29,89-121`). Backpressure completes writer, sends 1011 (bounded server close to 1 s); receive-side exit then performs same End cleanup; if peer does not react to close, the receive loop has no explicit abort on writer failure (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:274-287,540-565,799-806,289-324`). Writer WebSocket errors are caught without terminating receive loop (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:540-565`).
- Upstream network close/WebSocketException invokes `Finish`, cancels live loops and publishes Closed; presenter disposes on the queued `SessionClosed` event (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:322-392,738-760`; `src/PresenterAi.Application/Presenting/Presenter.cs:338-345,1814-1827`). A server `session.closed` does the same (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:553-555`). `Finish` itself does not dispose the socket: it depends on the consumer processing Closed (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:738-760`).
- Server shutdown: singleton presenter/bridge are registered (`src/PresenterAi.Infrastructure/DependencyInjection.cs:139-145`; `src/PresenterAi.Api/Realtime/PresenterBridge.cs:833-840`). Bridge `DisposeAsync` disposes presenter; presenter queues Shutdown, closes its active session by `DisposeAsync` (immediate abort), then cancels loop (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:501-507`; `src/PresenterAi.Application/Presenting/Presenter.cs:226-246,408-426`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:278-299`). No explicit `IHostApplicationLifetime.ApplicationStopping` cancellation hook appears in API registration; shutdown waits for currently executing event-loop work (notably start/connect) before queued Shutdown runs (`src/PresenterAi.Application/Presenting/Presenter.cs:296-309,408-426,491-493,543-589`). Abrupt process kill cannot send a close handshake; socket destruction is OS-driven.
- CLI `run` defaults to 300 s `--max-seconds`, then requests End and waits 8 s for Closed; service-provider disposal in the caller is the final presenter cleanup (`src/PresenterAi.Cli/Program.cs:318-356`; `src/PresenterAi.Cli/RunCommand.cs:27-30,205-235`). `smoke` has a 20 s output observation and `finally` disposes session even on failure (`src/PresenterAi.Cli/SmokeCommand.cs:82-125`). CLI `Main` passes `CancellationToken.None` and does not register Ctrl+C handler: normal console termination relies on process teardown, not a guaranteed graceful `session.close`; caller-supplied cancellation in `RunWithPresenterAsync` also falls into `finally` for recorder but no explicit End there (`src/PresenterAi.Cli/Program.cs:13-18`; `src/PresenterAi.Cli/RunCommand.cs:186-256`).
- Exceptions: presenter handles start/command exceptions per command; an unexpected event-handler exception escapes `RunLoopAsync` (only lifetime cancellation is caught), potentially leaving `_session` open until host disposal; End close failures attempt disposal but set idle before disposal (`src/PresenterAi.Application/Presenting/Presenter.cs:295-435,1772-1827`). A non-WebSocket exception in the live send loop is not caught there; receive loop catches general exceptions and finishes (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:301-399`).

## Idle bounds, retries, and ownership

- No server-side idle timeout or hard live-session duration in bridge/presenter; `ping` only replies to a client-initiated frame and does not arm a liveness deadline (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:289-324,392-393`; `src/PresenterAi.Application/Presenting/Presenter.cs:30-37,1772-1811`). Authentication *before ownership* has `Session:AuthFrameTimeoutSeconds` = 5 s (`src/PresenterAi.Infrastructure/Redis/SessionRedisOptions.cs:6`; `src/PresenterAi.Api/Realtime/PresenterBridge.cs:178-204`). Authenticated but never-started client holds the exclusive slot indefinitely without an upstream; started, silent browser leaves upstream open (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:122-155,289-324`).
- Pause clears progress timers but does not call Close; mute still leaves socket open; `SendAudioCore` accepts audio in paused state and the live silence pump continues every 20 ms while open (`src/PresenterAi.Application/Presenting/Presenter.cs:1686-1701,1741-1770`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:399-445`). Waiting-on-slide and question/confirmation holds block progress; question hold 15 s only releases in eligible states, interaction confirmations have 8/10 s transitions and none is a hard session cutoff (`src/PresenterAi.Application/Presenting/Presenter.cs:32-35,1033-1107,1886-1910,1960-1989`). Last slide wrap-up has 15 s fallback only when no output and no question hold (`src/PresenterAi.Application/Presenting/Presenter.cs:1590-1622`). `Presenter:AdvanceSilenceMs` defaults 3000 and `Presenter:FollowUpWaitMs` defaults 5000 (bounded 2500–60000); these are progression, not billing caps (`src/PresenterAi.Infrastructure/Live/PresenterOptions.cs:5-16`; `src/PresenterAi.Application/Presenting/Presenter.cs:2076-2078`). `_usageSeconds` only records updates and final usage; never tests a budget (`src/PresenterAi.Application/Presenting/Presenter.cs:68,618-619,1127,1849-1855`).
- Live handshake 10 s and close 5 s are `LiveSessionOptions` defaults, not config keys; connection reset can perform one extra client-delegation handshake on rejection (`src/PresenterAi.Infrastructure/Live/LiveSessionOptions.cs:3-12`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:83-169`). `MaxUpstreamAttempts=4`, but factory returns null beyond configured routes (primary plus optional fallback); failed candidate is disposed before next candidate and reset aborts/disposes the previous socket before replacement (`src/PresenterAi.Application/Presenting/Presenter.cs:36,543-593`; `src/PresenterAi.Infrastructure/DependencyInjection.cs:169-180`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:151-169`). Handshake timeout may be repeated for each delegation retry/route; no infinite retry loop (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:83-116`; `src/PresenterAi.Application/Presenting/Presenter.cs:543-600`). Successful session belongs to presenter until Closed or Shutdown; failed candidate uses `DisposeSessionAsync`; however exceptions between successful Connect and assignment `_session` (e.g. callbacks/logging) are caught and disposed, while exceptions *after* assignment in Start outside retry block can leave it owned until host disposal (`src/PresenterAi.Application/Presenting/Presenter.cs:543-624,408-426`).

## Other billed work / verification

- Delegation is hosted inside the live upstream via `session.start` responses model and optional hosted `web_search`; no separate HTTP delegation cancellation/token or per-response timeout visible here. Closing the upstream is the effective stop; `response.completed` / hosted activity are only observed, not bounded by their own watchdog (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:573-624,674-730`; `src/PresenterAi.Application/Presenting/Presenter.cs:1479-1492`).
- Tool calls run as background tasks with per-tool `WaitAsync` timeout (default `ITool.Timeout` 5 s, MCP `Tools:Mcp:CallTimeoutSeconds` default 10 s); timeout is linked to the tool timeout, **not presenter lifetime**, so End does not immediately cancel an in-flight call; late completion is dropped by session/generation checks (`src/PresenterAi.Application/Tools/ITool.cs:20-26`; `src/PresenterAi.Application/Presenting/Presenter.cs:1356-1403,1772-1791`; `src/PresenterAi.Infrastructure/Tools/ExternalToolsOptions.cs:10-14`). MCP invocation has an additional call timeout and at most one auth retry or reconnect/retry on eligible calls; token refresh before the inner timeout or confirmed-call refresh/reconnect can exceed inner bound, though outer `WaitAsync` gives up (`src/PresenterAi.Infrastructure/Tools/Mcp/McpTool.cs:81-197`). Giving up does not guarantee a non-cooperative remote call stops (`src/PresenterAi.Application/Presenting/Presenter.cs:1356-1379`). Tool-set disposal at End is fire-and-forget; late tool loads are observed/disposed, not synchronously awaited by End (`src/PresenterAi.Application/Presenting/Presenter.cs:1469-1507,1772-1792`). Startup MCP load uses `Tools:Mcp:StartBudgetMs` default 3000 plus presenter observation allowance 1000; server tasks use cancellation and failed partial connections are disposed (`src/PresenterAi.Infrastructure/Tools/Mcp/McpSessionToolSource.cs:19-85`; `src/PresenterAi.Infrastructure/DependencyInjection.cs:190-195`). OAuth/tool management HTTP calls are separate request operations, using request cancellation or tool tokens, rather than maintaining the billed voice session (`src/PresenterAi.Infrastructure/Tools/Mcp/McpOAuthService.cs:38-40,230-231,328-355`; `src/PresenterAi.Infrastructure/Tools/ExternalToolsServiceCollectionExtensions.cs:25-39`).
- Logs show upstream socket open, session started (id/model/expiry), close reason and seconds/silence; close timeout explicitly warns final usage unconfirmed (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:143-148,268-274,570-574,738-760`). Presenter publishes Usage and Closed frames to browser and logs close with unconfirmed marker (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:65-72`; `src/PresenterAi.Application/Presenting/Presenter.cs:1849-1863`). Recorder stores `EndedAt`, rounded `UsageSeconds`, `CloseReason`; absent final seconds falls back to last usage or 0, not an independently measured billed wall-clock duration, and DB finalization may fail (`src/PresenterAi.Infrastructure/Sessions/SessionRecorder.cs:333-383`). CLI emits usage and close reason; for confirmed billing reconcile provider-side records against these, rather than treating local zero/unconfirmed as zero charge (`src/PresenterAi.Cli/RunCommand.cs:171-184,205-235`).

## Ranked gaps and smallest proof

1. **High — unbounded billed idle** (pause, silent/stalled slide, background/live-but-silent peer, waiting/confirmation): add server-enforced maximum live wall-clock lifetime and separate configurable pause/idle deadline; force `Terminate`/End regardless of slide state, and expose remaining time. Test with fake time: paused/stalled/held session closes and disposes by deadline without any browser input (`src/PresenterAi.Application/Presenting/Presenter.cs:1556-1586,1686-1701,1886-1910`; `src/PresenterAi.Infrastructure/Live/LiveSession.cs:399-445`).
2. **High — undetected dead browser / writer failure**: add server-initiated heartbeat with pong/command deadline (or explicit periodic WebSocket ping/pong enforcement), abort failing writer's socket; route all exits through bounded End. Test authenticated silent peer with blackholed receive/writer and assert upstream abort/disposal and released slot (`src/PresenterAi.Api/Realtime/PresenterBridge.cs:289-324,392-393,540-565`).
3. **Medium — startup/shutdown/error orphan windows**: link shutdown to an independent active-session cancellation/abort, wrap presenter event loop in `finally` cleanup, and keep start candidates under an unconditional `try/finally` until ownership transfer; do not free browser slot while a start still may open upstream. Test disposal during hanging connect, post-connect throw, unexpected handler throw and 90 s start-observation expiry: no socket survives (`src/PresenterAi.Application/Presenting/Presenter.cs:226-246,296-435,543-624`; `src/PresenterAi.Api/Realtime/PresenterBridge.cs:140-173,624-672`).
4. **Medium — CLI cancellation**: register console cancellation and explicitly End/Dispose in `RunWithPresenterAsync` `finally` (while retaining provider disposal as backstop); test cancellation mid-talk and during startup, asserting close/abort without waiting on max-seconds (`src/PresenterAi.Cli/Program.cs:13-18`; `src/PresenterAi.Cli/RunCommand.cs:186-256`).
5. **Medium — post-End external work**: link per-run cancellation to all tool invocations/startup operations, cancel at End and await bounded cleanup; leave per-call timeout and one-retry policy intact. Test End during MCP request/refresh/approved call: cancellation observed, no retry after End, no live connections left (`src/PresenterAi.Application/Presenting/Presenter.cs:1356-1379,1440-1507,1772-1792`; `src/PresenterAi.Infrastructure/Tools/Mcp/McpTool.cs:81-197`).
6. **Low — unverifiable final billing duration**: record local start/end wall-clock, confirmed-vs-estimated usage flag, and explicit upstream-socket disposed metric/log (tagged with session id/route); test close timeout persists unconfirmed duration rather than misleading zero and emits disposal event (`src/PresenterAi.Infrastructure/Live/LiveSession.cs:268-299,738-760`; `src/PresenterAi.Infrastructure/Sessions/SessionRecorder.cs:333-383`).
